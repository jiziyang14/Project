# 设计规范

\*\*定位\*\*：面向高密度数据监测场景的通用视觉设计语言
\*\*核心视觉隐喻\*\*：玻璃质感载片上的精密测量仪表 —— 信息承载于半透介质表面，秩序优先于视觉装饰
\*\*执行原则\*\*：以克制为基准，允许在场景需要时适度灵活；所有灵活调整均需保证整体风格统一、简洁优雅，不破坏数据核心地位，不落入俗套，不影响渲染性能。

\---

## 一、核心设计原则

本系统以「数据的精密载体」为终极目标，通过四项底层原则构建差异化视觉语言。所有规范以原则为基准，具体执行可根据场景适度灵活，核心底线不可突破。

1. **材质优先，而非样式堆叠**
界面的高级感来自统一的材质物理逻辑，而非零散的装饰性样式。通过半透明、背景模糊、高光与阴影的组合模拟玻璃质感，区别于普通扁平化色块与廉价毛玻璃效果。可根据层级需求适度调整材质强度，前提是全系统逻辑一致。
2. **色彩即信号，出现即信息**
全界面以唯一功能性强调色为主，功能色默认低存在感。色彩的核心作用是传递状态与引导交互，而非纯装饰。允许在可视化、重点区域适度扩大强调色占比，或使用低饱和渐变增强层次，禁止无意义的色彩堆砌与炫技式配色。
3. **单重心秩序，拒绝平铺均衡**
每一个视图单元原则上有且仅有一个视觉重心，通过宽度权重、材质等级、光影层级强制建立阅读优先级。非对称布局是默认方案，特殊场景下可使用均衡布局，前提是仍能通过内容权重形成清晰的视觉流，不出现多元素抢夺注意力的情况。
4. **像素级严谨，克制为底限**
所有装饰性元素均需论证必要性。界面的精致感来自像素级严谨对齐、微妙的明暗过渡与统一的网格节奏。允许适度添加装饰、动效与辅助信息，前提是服务于信息传达，不冗余、不喧宾夺主，保持整体冷静精密的气质。

## 二、基础设计令牌

所有组件与布局均基于以下原子令牌构建，核心参数为默认基准，可在规范范围内灵活调整。

### 2.1 排版系统

**字体栈**

```css
font-family: 'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
font-feature-settings: 'tnum', 'cv11'; /\\\* 启用等宽数字与优化字形，确保数值对齐 \\\*/
```

**字重层级（严格保留4档，禁止使用中间值）**

* 700：核心数值整数位
* 600：区域标识、选中态文本
* 500：辅助信息、数值小数位
* 400：正文内容

**文本角色规格**

|文本角色|字号|字重|字距|行高|大小写|执行规则|
|-|-|-|-|-|-|-|
|核心度量值|2.2rem|整数位700 / 小数位500|-0.02em|1.1|无|小数位明度降低30%，与整数位基线严格对齐|
|区域标识|0.7rem|600|0.06em|1.2|全大写|明度低于正文，模拟仪表刻度标签的视觉权重|
|正文内容|0.875rem|400|0|1.5|正常|标准阅读对比度|
|辅助标注|0.75rem|500|0.01em|1.4|正常|低明度，用于单位、次要说明|

> 排版逻辑遵循仪表阅读顺序：先识别数值，再确认单位，最后查看标签。数值永远是卡片的第一视觉落点。

### 2.2 色彩体系

遵循「低饱和、统一色偏、信号化」原则，全界面色板以7色为基础，允许扩展同色系深浅变体。所有色值可直接使用。

#### 功能色板

|色值|命名|语义|执行规则|

|`#0EA5E9`|晴空青|运行中 / 可交互 / 选中|核心强调色。原则上单屏低面积占比，核心可视化、主操作区等场景可适度放宽；禁止无意义大面积铺色|
|`#F59E0B`|琥珀橙|警告 / 异常 / 待关注|默认低存在感，触发警告状态时强化显现|

* 允许使用**同色系低饱和渐变**用于背景、可视化图形、按钮状态增强，渐变需柔和、弱对比，禁止高反差炫彩渐变
* 允许为图标、符号添加微弱的同色系渐变或阴影，用于提升质感，需控制强度，避免抢夺数据注意力
* 禁止使用与主色板无关的高饱和装饰色，禁止多色彩无序堆砌

### 2.3 空间标尺

基于4px基础网格构建，所有间距均为4的倍数，形成可预期的视觉节奏。所有元素严格对齐基线网格。

|令牌值|应用场景|
|-|-|
|24px|页面基底内边距、主卡片内边距|
|20px|卡片间距、区块间距|
|18px|辅助卡片内边距|
|12px|元素内部纵向间距|
|6px|符号与文字间距、紧凑元素间距|
|4px|基线网格单位、微调间距|

### 2.4 玻璃质感材质系统

这是本系统的核心差异化特征。采用「四层CSS结构」模拟玻璃质感，所有属性均可通过标准CSS实现。允许根据层级需求调整参数，需保证全系统分级逻辑一致。

#### 四层结构（从下到上，对应CSS属性）

1. **透射层**：半透明白色背景（`background: rgba()`），控制底色透出程度
2. **模糊层**：背景模糊（`backdrop-filter: blur()`），模拟磨砂漫透射效果
3. **表面高光层**：顶部内阴影（`box-shadow: inset 0 1px 0 rgba()`），模拟玻璃表面的光线反射
4. **边缘厚度层**：底部极弱内阴影（`box-shadow: inset 0 -0.5px 0 rgba()`），模拟玻璃的厚度边缘

#### 材质分级规范（基准参数）

|层级|透射层（背景色）|模糊层（backdrop-filter）|表面高光层|边缘厚度层|应用场景|
|-|-|-|-|-|-|
|L1 低悬浮|`rgba(255,255,255,0.82)`|`blur(8px)`|`inset 0 1px 0 rgba(255,255,255,0.5)`|`inset 0 -0.5px 0 rgba(30,41,59,0.06)`|普通数据卡片、次级面板|
|L2 中悬浮|`rgba(255,255,255,0.88)`|`blur(12px)`|`inset 0 1px 0 rgba(255,255,255,0.65)`|`inset 0 -0.5px 0 rgba(30,41,59,0.08)`|核心指标卡片、聚焦态组件|
|L3 高悬浮|`rgba(255,255,255,0.94)`|`blur(16px)`|`inset 0 1.5px 0 rgba(255,255,255,0.8)`|`inset 0 -1px 0 rgba(30,41,59,0.1)`|弹窗、下拉面板、临时浮层|

> 灵活规则：允许为特殊组件添加微弱渐变底色、内发光等质感增强效果，需保持低透明度、弱对比，与整体玻璃质感统一；禁止堆砌多层效果导致厚重、俗套。

### 2.5 光影系统

阴影与材质共同描述元素的视觉层级，采用「三层阴影结构」，通过多层box-shadow叠加实现。允许根据层级需求调整阴影强度，核心要求是全系统光影逻辑统一。

#### 三层阴影结构（对应CSS多值box-shadow）

1. **环境漫射影**：大范围、低不透明度软阴影，描述整体悬浮感
2. **接触阴影**：小范围、稍深的阴影，模拟元素底部与底面的接近关系
3. **补正内阴影**：与材质边缘层配合，强化厚度感

#### 光影分级参数（基准参数）

|层级|环境漫射影|接触阴影|对应视觉层级|
|-|-|-|-|
|L1|`0 4px 24px rgba(30,41,59,0.05)`|`0 1px 2px rgba(30,41,59,0.04)`|基础悬浮卡片|
|L2|`0 8px 36px rgba(30,41,59,0.07)`|`0 2px 4px rgba(30,41,59,0.05)`|重点提升卡片|
|L3|`0 16px 56px rgba(30,41,59,0.1)`|`0 4px 8px rgba(30,41,59,0.08)`|顶层浮层弹窗|

> 交互反馈规则：元素被按下/选中时，阴影范围收窄、不透明度提升，模拟玻璃片被按下、更接近底面的视觉效果，而非放大或变色。
>
> 灵活规则：允许为按钮、图标等交互元素添加微弱阴影增强质感，需保持柔和、低存在感，禁止强阴影、硬阴影破坏整体轻盈感。

### 2.6 动效规范

动效核心作用是传递状态变化，优先保证简洁高效。允许在必要场景适度扩展动效类型，禁止滥用、禁止花哨。

#### 标准动效参数

|动效类型|时长|应用场景|
|-|-|-|
|状态过渡|200ms|阴影变化、边框颜色、悬停反馈、位置变化|
|数据变更|250ms|图表维度变化、进度过渡、数值淡入跳变|
|信号呼吸|2000ms 无限循环|运行状态脉冲光晕，透明度在0.4\~0.8间循环|

#### 允许的动效（基准+扩展）

* 数据刷新时数值淡入跳变（优先方案，数字滚动为可选补充）
* 状态切换时阴影与透明度平滑过渡
* 运行状态下脉冲圆点的呼吸光晕
* 图表数据维度的高度/长度平滑过渡
* **可感知加载场景下**的极简加载动效、轻量骨架屏（需风格统一、样式极简，禁止花哨的跳动/闪烁）
* **关键操作场景下**的轻量反馈特效（如提交成功、错误提示），需克制、短暂，禁止每步操作都触发

#### 强制规则

* 所有系统反馈（提示、确认、告警、弹窗）必须使用**自定义组件实现**，禁止调用浏览器原生弹窗（alert/confirm）、原生提示框等默认控件，确保视觉语言完全统一，避免原生控件的违和感
* 所有动效统一使用 `ease-out` 缓动曲线，保持利落、不拖沓的体感
* 所有动效需保证渲染性能，避免造成页面卡顿、掉帧

#### 不推荐的动效（非绝对禁止，需严格评估必要性）

* 大面积入场动画
* 庆祝类、夸张的成功反馈特效（这个在特定场合允许，不必过于拘泥，具体要求参考Requirements.md的功能要求）
* 翻转、缩放、3D变换等装饰性强的动效

### 2.7 仪表示符系统

使用纯CSS绘制的极简几何符号作为状态与指标标识，形状语义恒定，仅通过颜色与填充传递状态。符号与文本基线对齐，间距统一6px。允许为符号添加微弱渐变、光晕增强质感，需控制强度。

|符号（如有需要可以扩展）|语义|尺寸规则|
|-|-|-|
|● 实心圆点|运行中 / 在线 / 正常|8px直径，可搭配外发光晕|
|◆ 实心菱形|指标项 / 正常数据点|8px边长|
|◇ 空心菱形|警告 / 异常项|8px边长，1px描边|
|▣ 实心方框|选中 / 聚焦 / 激活|8px边长|
|〰️ 波形线|趋势 / 波动 / 时序|高度12px，单线条|
|─ 基准线|参考值 / 阈值线|1px虚线，贯穿容器|

## 三、布局系统

### 3.1 页面三层结构

页面自上而下分为三个功能区，为默认推荐结构，可根据产品需求调整。结构通用，不绑定具体功能内容。

1. **顶部全局栏**

   * 高度固定56px，采用L1低悬浮材质
   * 左侧放置系统标识，右侧放置全局状态与主操作入口
   * 与下方内容区通过20px间距分隔，**限制使用实体分割线**
2. **核心度量区**

   * 推荐采用非对称多栏布局：1个主度量卡片 + N个次度量卡片
   * 推荐规则：主卡片宽度 ≥ 同行次卡片的1.5倍
   * 用于承载当前视图中优先级最高的核心数据
3. **分析详情区**

   * 上层推荐采用非对称分栏布局，主内容区占比60%，次内容区占比40%
   * 下层可采用等分布局，承载次级分析模块
   * 卡片之间统一保持20px间距

### 3.2 权重网格规则

* **推荐原则**：每一行布局有且仅有一个主角区块，其余为辅助区块；主角区块与次要区块的宽度比至少为 3:2
* **灵活范围**：特殊业务场景下可使用均衡布局，前提是通过内容复杂度、材质层级自然形成视觉重心，避免出现所有元素平均用力、平铺分散注意力的情况
* **通用要求**：通过基线对齐、参考线延续性引导阅读路径，保持整体秩序感

## 四、组件规范

### 4.1 数据卡片

信息区块的基础容器，严格遵循玻璃质感材质规范。允许适度添加装饰增强层级，需保持克制。

#### 标准结构（自上而下）

1. **标识区**：0.7rem全大写宽字距标签，定义数据域
2. **度量区**：核心数值 + 浅色辅助单位
3. **补充区（可选）**：辅助说明、趋势符号、迷你可视化

#### 变体规格

|类型|内边距|材质等级|应用场景|
|-|-|-|-|
|主卡片|24px|L2 中悬浮|核心指标、主可视化容器|
|辅助卡片|18px|L1 低悬浮|次级数据、分类统计、功能模块|

> 灵活规则：不推荐添加顶部彩色条、侧边装饰条等强装饰元素；如确需区分卡片类型，可通过微弱的顶部渐变、图标颜色差异实现，需保证低存在感、不抢夺数据注意力。
>
> 圆角规则：卡片圆角基准8px，可在6-12px范围内微调，禁止大于12px的大圆角，避免破坏精密感。

### 4.2 操作按钮

遵循「默认隐形，交互显形」的核心原则，允许适度添加质感增强。

|按钮类型|默认态|悬停态|应用场景|
|-|-|-|-|
|次要按钮|半透明白底、1px浅灰边框、灰色文字|边框与文字变为晴空青|次级操作、筛选、切换|
|主按钮|深空灰蓝实心背景、白色文字|背景明度微降|核心操作、确认、提交|
|警告按钮|琥珀橙实心背景、白色文字|背景明度微降|危险操作、二次确认|

> 通用规则：圆角统一6px，高度32px，水平内边距16px。允许添加微弱阴影、同色系渐变增强质感，需保持低调，禁止花哨的渐变、强阴影、厚重立体效果。

### 4.3 数据可视化

遵循「数据自描述」的核心原则，以精简为基准，允许根据信息复杂度灵活补充辅助元素。

* **时序类图表**：默认仅保留波形线条与两条极淡参考虚线，隐藏坐标轴文字与刻度；数据复杂、需精确定位的场景，可补充极简坐标轴与刻度，需低明度、弱存在感
* **占比类图表**：默认扇区内直接标注占比，中心挖空显示总量；数据类别较多时，可补充极简外置图例，需样式简洁、不占用过多空间
* **对比类图表**：默认单色柱体，仅高亮项使用强调色；数值标注于柱顶
* 通用规则：优先保证数据清晰可读，辅助元素（图例、坐标轴、网格线）按需添加，始终保持低明度、弱对比，不抢夺数据图形的视觉重心；允许使用同色系渐变美化图形，禁止色彩堆砌。

### 4.4 输入控件

遵循「玻璃刻字」视觉隐喻，弱化容器感，强化输入行为本身。

* 默认态：透明背景，底部1px浅灰边框，无其余边框
* 聚焦态：底部边框变为晴空青，宽度保持1px，无外发光
* 禁用态：文字与边框变为浅灰，背景保持透明
* 输入文字使用0.875rem正文字号，占位符使用低明度雾灰色

## 五、设计原则与反模式

### 严格禁止（底线规则，不可突破）

1. **禁止使用实体分割线做区域划分**，改用间距、材质层级区分，保持界面通透干净
2. **禁止界面出现内部编号、调试信息**，所有面向用户的文本必须使用业务化、用户视角的表述
3. **禁止使用浏览器原生弹窗、原生提示框等默认控件**，所有反馈与交互必须自定义实现，保证视觉统一
4. **禁止高饱和、多色彩的无序堆砌**，禁止与主色板无关的炫彩装饰

### 不推荐 / 需谨慎使用（可按需使用，需满足前提）

1. 不推荐大面积渐变、强对比渐变，仅允许低饱和同色系渐变用于质感增强
2. 不推荐花哨的加载动效、夸张的反馈特效，仅允许极简、轻量的动效用于必要场景
3. 不推荐所有卡片等宽平铺的均衡布局，优先使用非对称布局建立视觉重心
4. 不推荐冗长的引导文案、冗余的辅助说明，文本需精简、直接，不照搬技术描述
5. 不推荐强阴影、硬阴影、厚重立体效果，保持整体轻盈通透的玻璃质感

\---

## 六、设计价值观总结

精密的最终气质，来自四个要素的高度统一：

1. **分层玻璃材质构建物质感** —— 用可落地的分层结构模拟真实玻璃质感，让界面拥有厚度与光影层次，区别于廉价毛玻璃
2. **非对称权重建立视觉秩序** —— 以单重心布局为默认方案，用秩序降低认知负荷，让注意力自然流向核心数据
3. **极简符号实现精确制导** —— 用恒定的几何形状传递稳定语义，实现最低成本的状态识别
4. **信号化色彩贯彻克制美学** —— 以色彩传递信息为核心，允许适度灵活扩展，始终保持冷静克制的整体基调

它以精密克制为底色，在保证数据核心地位的前提下保留适度的灵活空间，最终呈现冷静、可靠、高级且不失细节的视觉体验。

## 一、色彩维度

|内容|原则要求|灵活范围|取舍逻辑|
|-|-|-|-|
|渐变色使用|优先使用纯色，保持干净质感|允许同色系低饱和渐变用于背景、可视化、图标质感增强；禁止高对比炫彩渐变|放弃炫彩渐变的视觉冲击力，换取统一的高级感；适度保留渐变的质感提升作用，避免界面过于单调死板|
|强调色占比|原则上保持低面积占比，作为信号点使用|核心可视化、主操作区等场景可适度放宽，禁止无意义大面积铺色|默认用小面积强调色保证信号的精准度；特殊场景扩大占比用于强化视觉重心，前提是不泛滥、不失去信号价值|
|图标/符号装饰|优先纯色极简|允许添加微弱阴影、同色系渐变提升质感，需低存在感|适度的质感提升不破坏整体简洁，同时避免图标过于扁平廉价|

### 二、动效维度

|动效性能|所有动效保证流畅不卡顿|禁止复杂、耗性能的动效|动效服务于体验，不能以牺牲性能、造成卡顿为代价|

### 四、布局与信息维度

|内容|原则要求|灵活范围|取舍逻辑|

### 五、材质与光影维度

|内容|原则要求|灵活范围|取舍逻辑|
|-|-|-|-|
|材质光影一致性|全系统遵循三级分级逻辑，风格统一|可根据组件层级调整强度，禁止风格跳脱|统一的材质光影是玻璃质感的核心，是本设计语言的识别标志；灵活调整是为了更好地区分层级，而非破坏统一性|
