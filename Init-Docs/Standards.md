# 1\. 项目上下文与绝对技术红线

你是一名资深全栈AI开发工程师，有如下要求：

* **语言与框架**：Python 3.10+，PyTorch。
* **绝对禁止引入**：任何大语言模型（LLM）、云端API调用（包括但不限于OpenAI、HuggingFace Inference）、在线知识库查询。
* **推理与存储**：所有模型推理必须在本地完成；所有数据、日志、模型权重只能存储在本地文件系统。
* **前端架构**：纯静态 HTML/CSS/JS 分离。
* **功能范围**：目前已确认的 **22项原子任务**（F1-1 至 F7-2），包含8个需训练的异构深度学习模型（Transformer时序分类器、ResNet-18+SimCLR对比学习、LSTM序列分类、MLP回归/二分类/三分类、DQN强化学习、二部图嵌入）。

# 2\. 目录与文档规范

* 目录要尽可能扁平化，功能具体清晰，解耦程度高。
* 每个目录下必须包含 `README.md`，至少说明：

  * 本目录的**单一职责边界**。
  * **上游依赖**（输入数据/配置来自哪个模块）与**下游消费者**（输出被谁使用）。
  * **核心输入输出数据流**（含张量形状或文件格式）。
* 项目根目录 `README.md` 需包含：整体架构图（可用ASCII）、运行环境、三行快速启动命令，以及各一级目录的功能索引等等。

# 3\. 模块化与解耦

* 每个深度学习模型（如 `b1\\\_transformer`）必须封装为**独立子包**，内含 `train.py`、`infer.py`、`config.yaml`、`model.py`（模型定义）、`dataset.py`（如需要）。

  * 子包间允许通过 import 直接引用对方内部变量、函数或类，但必须通过 api.py 模块进行隔离，确保单个子系统的错误不波及整体。同时，也可通过以下正式接口交互：
  * **标准数据类（dataclass）**：所有跨模块传递的数据结构必须定义在共享的 `core/schemas.py` 中，并在 `AI\\\_CONTEXT.md` 的数据协议字典中登记。
  * **配置文件**：上游模块可输出yaml路径供下游读取，但下游不得假设上游的内部文件结构。
* 任何模块崩溃或训练失败不得影响主调度器对其它模块的调用。主调度器应捕获异常并记录，然后继续执行。
* 每个子包必须拥有独立的单元测试入口（`test.py` 或 `tests/` 目录），支持单独运行。

# 4\. 版本管理策略（本地归档 ）

* 项目整体采用**本地文件夹归档**作为版本回退手段。仅在发生核心框架重大重构（如更换backbone、修改全局数据协议）且回滚成本极高时，允许创建 `-OLD` 备份文件夹，并必须在同级生成 `VERSION\\\_MIGRATION.md`，详细记录变更原因、影响范围与迁移步骤。
* **禁止滥用备份文件夹**。日常功能迭代以文件增量修改为主，严禁因微小改动创建“xx\_v2\_old”等冗余副本。
* **依赖固化要求**：项目根目录必须存在 `requirements.txt`，并注释说明每个依赖的用途。该文件与备份文件夹一并维护，确保任何时间点的代码快照均可通过 `pip install -r requirements.txt` 复现运行环境。

# 5\. UI 架构设计（纯静分离与信息隐藏）

* 前端必须严格遵循 **HTML/CSS/JS 完全分离**：

  * `index.html` 仅承载DOM骨架，不允许包含 `<style>` 或 `<script>` 块。
  * 所有样式归入 `css/` 目录，按页面或组件拆分文件。
  * 所有交互逻辑归入 `js/` 目录，使用模块化写法（ES6 modules，但不依赖打包工具），入口文件为 `js/main.js`。
* **强制信息隐藏**：严禁将任何开发指令、调试信息、模型输出中间结果、AI对话提示、系统内部状态直接渲染到用户可视界面上。用户界面文本必须为面向最终用户的干净业务语言。调试输出仅允许出现在浏览器开发者工具的控制台中，且必须通过 `console.debug` 输出，并在生产环境可一键禁用。
* 前端不得发起任何外部网络请求，所有数据通过本地文件或内置的模拟服务获取。
* 前端如果有需要可以采用多个模块多个文件，禁止一味的铺大饼，具体要求参考Design.md的标准。

# 6\. 编码与注释标准（意图驱动）

* 采用简明的中文注释。
* **所有代码**必须包含 **Google 风格 Docstring**，必须详细描述 `Args`、`Returns`、`Raises`。
* **代码注释黄金法则**：注释可以说明\*\*业务逻辑原因（Why）、\*\*代码操作（What）。禁用“新增”、“修改”、“删除”等临时性动词，以及“TODO: 有待优化”等模糊标记。
* 注释统一使用**陈述性中文**描述设计意图与约束，示例：

```python
  # 冻结前7层以保留预训练视觉特征，仅让最后1层适配本系统的截图差异任务
  # 计算InfoNCE损失用于自监督对比学习，温度系数设为0.07以平衡梯度与区分度
  ```

* 变量与函数命名必须见名知意，禁止使用单字母变量（循环变量 `i`、`j` 在明确上下文时除外，但张量维度下标除外）。

# 7\. 冒烟测试与快速验证骨架

* 在根目录 `tests/smoke/` 下，为每条核心功能链编写最小化冒烟测试脚本。每个脚本应能在30秒内运行完成，仅使用假数据验证模块骨架能正确初始化、数据能正确流过，不追求精度。
* 每个子模块的 `README.md` 末尾必须包含 **“Quick Run”** 小节，提供可直接复制执行的命令（如 `python -m modules.b1\\\_transformer.infer --mock`），确保任何开发者能在5分钟内跑通该模块的骨架，确认环境无误。
* 冒烟测试脚本在通过时应输出明确的成功标志，失败时抛出异常并输出错误上下文。

# 8\. 数据协议契约与运行时校验

* 所有在 `AI\\\_CONTEXT.md` 中登记的数据结构，必须在 `core/schemas.py` 中定义为 `dataclass`，并使用 `typeguard` 或手写 `\\\_\\\_post\\\_init\\\_\\\_` 进行类型和形状的严格校验。
* 在模块间数据传递的关键节点（如调度器调用模型推理前），必须插入**维度断言**，例如：

```python
  assert mouse\\\_tensor.shape == (batch\\\_size, 50, 3), f"鼠标数据维度不匹配，期望(batch,50,3)，得到{mouse\\\_tensor.shape}"
  ```

确保错误在第一时间被发现，避免畸形数据传播至下游导致难以追溯的异常。

* 所有使用配置文件加载的数值，必须在加载后校验其合法范围（如学习率>0，dropout率在\[0,1)），校验失败则立即终止并给出明确错误信息。

# 9\. 模型训练与评估标准化

* 每个模型的训练脚本 `train.py` 必须实现：

  * **Checkpoint管理**：自动保存验证集损失最低的模型权重，文件名包含epoch和loss值。
  * **指标输出**：每个epoch结束后必须在控制台打印训练损失、验证损失以及至少一项任务相关指标（准确率、F1、MSE等）。
* 每个模型子包必须包含 `evaluate.py`（或 `infer.py` 支持评估模式），能够加载最佳checkpoint并输出标准化评估报告（文本格式），报告需包含指标值及评估样本数。
* 所有随机性操作必须在 `train.py` 中通过命令行参数或config设置随机种子，确保结果可复现。
